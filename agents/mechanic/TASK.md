# 주간 점검 지시

## 권한

저장소 파일을 **읽을 수 있다**. Read·Glob·Grep을 써서 직접 확인해라.
다만 **어떤 파일도 수정하거나 생성하지 마라.** 보고서는 응답 본문으로 출력한다.

## 할 일

저장소를 한 바퀴 돌며 아래를 점검하고, 찾은 것을 보고서로 쓴다.

## 점검 목록

1. **문서와 실제의 어긋남**
   - README에 적힌 명령이 package.json의 scripts에 실제로 있는가
   - README의 디렉터리 구조가 실제 구조와 맞는가
   - 주석이 설명하는 동작이 코드와 일치하는가

2. **쌓이기만 하는 것**
   - `work/` 아래 파일 수가 관리 가능한 수준인가
   - `agents/*/memory.md`가 상한(30줄)을 넘지 않았는가

3. **워크플로**
   - `.github/workflows/`에서 `pull_request_target`을 쓰는 곳이 있는가 (있으면 심각)
   - `permissions:`가 필요 이상으로 넓게 열려 있는가
   - 참조하는 액션 버전이 낡았는가

4. **설정 정합성**
   - `crew.json`의 각 에이전트에 대응하는 `agents/<id>/` 폴더가 있는가
   - 워크플로에 등록되지 않은 에이전트가 있는가
   - `output` 경로가 실제로 쓰이는가

5. **테스트**
   - `scripts/lib/` 아래 모듈 중 테스트가 없는 것이 있는가

## 출력 형식

```
# {YYYY-MM-DD} 저장소 점검

> 한 줄 총평.

## 발견

### {제목}

{무엇이 문제인지. 어디서 어떻게 드러나는지.}

**위치** `경로:줄번호`
**고치는 법** {구체적으로}

### {제목}
...

## 이상 없던 것

- {점검했고 문제없던 항목}
```

발견이 없으면 "## 발견" 아래에 `이번 주 이상 없음.`이라고만 쓴다.

## 마지막 블록

기억은 항상 붙인다.

```
===MEMORY===
- {이번 주 점검에서 발견한 것 요약. 없으면 "이상 없음"}
```

**발견이 하나라도 있을 때만** 그 아래에 이슈 본문을 덧붙인다.
발견이 없으면 이 블록을 통째로 생략한다.

```
===ISSUE===
{발견 항목만 간추린 이슈 본문. 체크박스 목록으로.}
```
