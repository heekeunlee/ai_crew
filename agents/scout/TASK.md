# 오늘의 근무 지시

## 중요: 파일을 읽으려 하지 마라

너에게는 파일 접근 권한이 없다. **필요한 것은 전부 이 메시지와 시스템 프롬프트에 이미 들어 있다.**

- 다룰 주제 → 시스템 프롬프트의 "다루는 주제" 목록
- 이미 다룬 것 → 이 메시지 아래의 "내 기억" 섹션

쓸 수 있는 도구는 웹 검색과 웹 페이지 열람뿐이다. 결과물은 파일로 저장하지 말고
**응답 본문으로 그대로 출력한다.** 저장은 실행 스크립트가 알아서 한다.

## 할 일

시스템 프롬프트에 나열된 각 주제에 대해 **최근 24~48시간 사이의 새 소식**을 찾아
아래 형식으로 요약본 한 편을 작성한다.

## 순서

1. 주제별로 웹 검색을 한다. 검색은 전체 8회까지만.
2. 찾은 것 중 **실제로 새롭고 실제로 중요한 것만** 고른다.
   - 홍보성 보도자료, 같은 내용의 재탕 기사는 버린다.
   - 한 주제에서 건질 게 없으면 그 주제는 통째로 건너뛴다. 억지로 채우지 않는다.
3. "내 기억"에 이미 있는 내용과 겹치면 건너뛴다.
4. **출처를 하나씩 검증한다.** 이 단계를 건너뛰지 마라.
   각 항목마다 스스로에게 묻는다 —
   - 이 URL이 **이 항목에서 말한 회사·제품**을 실제로 다루는 페이지인가?
     (예: Broadcom 이야기인데 링크가 다른 종목 페이지면 실격)
   - 검색 결과 목록이나 "오늘의 뉴스 모음" 같은 **묶음 페이지**는 아닌가?
   - 공식 블로그·릴리스 노트·보도자료 원문·거래소 공시로 **바꿀 수 있는가**?

   셋 중 하나라도 걸리면 **1차 출처를 다시 찾는다.**
   그래도 못 찾으면 **그 항목을 뺀다.** 항목 수를 채우려고 엉뚱한 링크를 달지 않는다.
   부득이 2차 출처를 쓸 때만 URL 뒤에 ` (2차)`를 붙인다.
5. 아래 출력 형식에 맞춰 쓴다.

## 출력 형식

정확히 이 구조로만 출력한다. 앞뒤에 인사말이나 설명을 붙이지 않는다.

```
# {오늘 날짜} 리서치

> 한 줄 총평. 오늘 흐름을 한 문장으로.

## 개발자 도구

### {제목}

{3~5문장. 무슨 일이 있었는지, 그리고 왜 중요한지.}

출처: {URL}

## 미국 증시

### {제목}
...

## 한국 증시

### {제목}
...

## AI 활용 트렌드

### {제목}
...

---

## 오늘 확인했지만 넘어간 것

- {제목} — {건너뛴 이유 한 줄}
```

주제별 섹션은 **건질 게 있는 것만** 넣는다. 빈 섹션은 아예 만들지 않는다.
맨 끝의 `---`와 "넘어간 것" 섹션은 한 몸이다. 넘어간 게 없으면 `---`도 쓰지 않는다.

## 마지막 블록 (필수)

응답 맨 끝에 반드시 아래를 붙인다. 이건 문서가 아니라 내일의 나에게 남기는 메모다.

```
===MEMORY===
- {오늘 다룬 주제를 쉼표로 나열. 한 줄.}
```

## 분량

주제당 1~2항목, 전체 4~8항목. "넘어간 것" 섹션은 없으면 생략한다.
