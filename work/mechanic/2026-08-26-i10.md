# 2026-08-26 저장소 점검

> Actions → mini 이전 자체는 깔끔하다. 다만 `poll.sh`의 이슈 폴링 경로에 두 가지 구멍이 있고, `work.sh`에 저장소 이름이 하드코딩된 곳과 README에 낡은 문구가 하나 남았다.

## 발견

### poll.sh가 "잠금으로 건너뛴 이슈"를 처리 완료로 기록한다

`poll.sh`는 이슈를 `work.sh`에 넘기기 **전에** 먼저 `SEEN`에 기록한다 (`poll.sh:42-43`, "성공이든 실패든 한 번 집어간 것으로 기록한다"). 그런데 같은 에이전트가 이미 다른 이슈를 처리 중이면 `work.sh`는 잠금에 걸려 아무 것도 안 하고 `exit 0`으로 조용히 끝난다 (`work.sh:41-49`, "이미 근무 중입니다. 건너뜁니다.").

두 동작을 합치면: 2분 폴링 주기 안에 같은 에이전트에게 온 두 번째 이슈는 — 실제로는 아무 근무도 안 했는데 — 영구히 "처리됨"으로 기록되고, 댓글도 안 달리고 닫히지도 않은 채 그냥 방치된다. `updatedAt`이 다시 바뀌기 전까지는 두 번 다시 집어가지 않으므로(`poll.sh:9` 주석 그대로), 사람이 다시 라벨을 붙이거나 댓글을 달지 않는 한 그 지시는 사라진 것과 같다. 에이전트 근무가 2분보다 길게 걸리는 건 흔한 일이라(웹서치 여러 번 도는 scout 등) 실전에서 부딪힐 수 있는 경로다.

`on-issue.yml`에는 이 문제가 없다. 이슈별 `concurrency: group: issue-${{ github.event.issue.number }}`로 큐잉되지, 조용히 버려지지 않는다.

**위치** `scripts/local/poll.sh:41-43`, `scripts/local/work.sh:41-49`
**고치는 법** `work.sh`가 잠금 때문에 건너뛴 경우를 구분할 수 있게 한다 (예: 전용 exit code, 예를 들어 `exit 75`). `poll.sh`는 그 exit code를 받으면 `SEEN`에 쓰지 않고 다음 폴링에서 다시 시도하게 한다. 지금처럼 디스패치 전에 무조건 기록하면 안 된다.

### poll.sh는 모르는 에이전트 라벨을 이슈에 알려주지 않는다

`on-issue.yml`은 `agent:` 라벨이 `crew.json`에 없는 에이전트를 가리키면 이슈에 댓글로 알려준다 (`on-issue.yml:56-64`, "모르는 에이전트면 알려주기" — 쓸 수 있는 라벨 목록까지 안내).

`poll.sh`의 같은 분기는 로그에 `echo`만 남기고 끝난다 (`poll.sh:35`). 이슈를 연 사람 입장에서는 아무 반응도 없이 조용히 무시된 것처럼 보인다.

**위치** `scripts/local/poll.sh:34-38`
**고치는 법** `on-issue.yml:62-64`처럼 `gh issue comment`로 "라벨 `agent:X`에 해당하는 에이전트가 없습니다. 쓸 수 있는 라벨: ..." 를 이슈에 남기는 한 줄을 추가한다.

### work.sh에 저장소 경로가 문자열로 박혀 있다

이슈 완료 댓글에서 산출물 링크를 만들 때 `https://github.com/heekeunlee/ai_crew/blob/main/$FILE`로 저장소 이름을 하드코딩했다 (`work.sh:141`). 바로 위 `poll.sh:21`은 같은 정보를 `gh repo view --json owner --jq .owner.login`으로 동적으로 얻는데, `work.sh`만 그렇게 하지 않는다. 지금 저장소 경로(`/Users/dasepa/ai_crew`)를 옮긴 이번 작업의 취지(박힌 경로 없애기)와 결이 안 맞는 곳이다.

**위치** `scripts/local/work.sh:141`
**고치는 법** `poll.sh`처럼 `gh repo view --json url --jq .url` (또는 `nameWithOwner`)로 한 번 구해서 변수로 쓴다.

### README의 "책상" 설명이 아직 Actions만 가리킨다

README 오피스 화면 표 (`README.md:105`)는 "책상 | Actions가 지금 돌고 있음 (모니터 켜짐)"이라고 적혀 있다. 그런데 `scripts/lib/state.mjs:46-53`을 보면 "working" 상태는 `startedAt`/`STALE_MS`만 보고 판정하며 실행 주체(Actions vs mini)를 구분하지 않는다. 지금 배경대로라면 정기 근무 5개는 전부 mini에서 도는데, 문구는 여전히 "Actions가"라고 못박아 놨다. 같은 파일 61~97번 줄은 이미 두 경로를 다 설명하고 있어서, 105번 줄만 옛 표현이 남은 것으로 보인다.

**위치** `README.md:105`
**고치는 법** "Actions가 지금 돌고 있음"을 "근무가 지금 돌고 있음" 정도로 실행 주체 언급 없이 고친다.
