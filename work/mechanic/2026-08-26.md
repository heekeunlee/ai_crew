# 2026-08-26 저장소 점검

> 문서·설정·테스트는 지난주 지적 사항이 반영돼 전부 정합하고, 이번 주는 워크플로가 참조하는 액션 버전이 여러 메이저 단계 뒤처진 것 하나만 새로 걸렸다.

## 발견

### GitHub Actions 참조 버전이 3세대까지 뒤처짐

`.github/workflows/` 전체에서 쓰는 `actions/checkout`·`actions/setup-node`·Pages 배포 액션이 모두 구버전에 고정돼 있다. GitHub 릴리스 페이지와 API(`/releases/latest`)를 각각 조회해 확인했다.

| 액션 | 저장소에서 쓰는 버전 | 최신 버전 |
|---|---|---|
| actions/checkout | v4 | v7.0.1 |
| actions/setup-node | v4 | v7.0.0 |
| actions/configure-pages | v5 | v6.0.0 |
| actions/upload-pages-artifact | v3 | v5.0.0 |
| actions/deploy-pages | v4 | v5.0.0 |

당장 워크플로가 깨진 것은 아니지만, checkout·setup-node는 메이저 3단계, Pages 배포 3종은 1~2단계씩 뒤처져 있다. 오래 방치할수록 한꺼번에 올릴 때 breaking change를 더 많이 만나게 된다.

**위치**
`.github/workflows/_agent.yml:40,42`
`.github/workflows/on-issue.yml:33`
`.github/workflows/test.yml:19,20`
`.github/workflows/pages.yml:29,30,35,36,40`

**고치는 법** 각 파일의 `uses:` 태그를 표에 적은 최신 버전으로 올린다 (`actions/checkout@v4` → `@v7.0.1` 등). `_agent.yml`은 재사용 워크플로라 한 번만 고치면 `scout.yml`·`quill.yml`·`curator.yml`·`mechanic.yml`이 부르는 근무 전체에 반영된다. 올린 뒤 `test.yml`의 배관 점검(`DRY_RUN=1`)이 그대로 통과하는지로 회귀를 확인한다.

## 이상 없던 것

- README 명령(`npm run scout`, `scout:dry`, `npm test`, `npm run state`)이 `package.json`의 scripts와 전부 일치
- README 디렉터리 구조도가 실제 파일 구조(`.github/workflows/*`, `scripts/lib/*.mjs` 5종, `scripts/local/*`)와 일치 — 지난주 지적된 `lib/schedule.mjs` 누락은 반영됨
- `scripts/lib/sections.mjs`의 주석이 설명하는 "줄 전체를 차지할 때만 표식으로 본다" 동작이 실제 구현 및 `sections.test.mjs`의 회귀 테스트와 일치
- `agents/*/memory.md` 4개 전부 "이미 다룬 주제" 항목이 3~10줄로, 상한 30줄에 여유 있음
- `work/scout`(5건)·`work/quill`(2건)·`work/mechanic`(3건) 모두 관리 가능한 수준
- `.github/workflows/`에 `pull_request_target` 사용 없음
- 워크플로 `permissions:`는 README에 적힌 대로 에이전트별 최소 권한(scout/curator: `contents:write`, quill: `+pull-requests:write`, mechanic: `+issues:write`)만 부여됨
- `crew.json`의 4개 에이전트(scout·quill·curator·mechanic) 모두 `agents/<id>/` 폴더와 대응 워크플로 파일을 가짐, 등록 누락 없음
- `output` 경로(`work/scout`, `work/quill`, `work/mechanic`, `archive/INDEX.md`) 전부 실제로 파일이 쌓이고 있음
- `scripts/lib/` 5개 모듈(`memory`·`output`·`sections`·`schedule`·`state`) 전부 대응하는 `*.test.mjs` 존재
