# 2026-10-19 저장소 점검

> 지난 한 달 사이 네 에이전트 전원이 GitHub Actions에서 2주 넘게 연쇄 실패한 사실이 git log에 그대로 남아 있었고, 지난주 보고서의 원인 진단("로컬 기계가 꺼져 있던 구간")은 틀렸다.

## 발견

### 1. 네 에이전트 전원이 Actions에서 2주 넘게 연쇄 실패했다 — 지난주 진단은 오진이었다

`git log --all --grep="근무 실패"`로 "🤖 OO 근무 실패 — 상태 정리" 커밋들이 전부 드러난다. 작성자가 예외 없이 `ai_crew[bot]` (= `github-actions[bot]`)이다 — **로컬 맥이 꺼져 있던 게 아니라 GitHub Actions 워크플로 자체가 돌다가 실패**했다는 직접 증거다.

- 2026-09-23 23:00 curator 실패를 시작으로 2026-10-04/05까지 거의 매일 실패가 이어졌다: curator 09-23~10-04(12일 연속) · scout 09-24~10-05(12일 연속) + 10-07 · quill 09-26·10-03(해당 주 PR 자체가 안 생김) · mechanic 09-28·10-05(메카닉 자신의 점검도 이 2주를 빠졌다).
- 산출물로도 확인된다: `work/scout/`에 `2026-09-23.md` 다음 파일이 `2026-10-06.md`다(그 사이 12일 공백). `archive/INDEX.md`를 건드린 커밋도 `2026-09-22` 다음이 `2026-10-05`다.
- 10-09~10-15는 정상 복구됐다가, 2026-10-16 23:00(curator, 커밋 `7c22aa0`)·10-17 07:00(scout, `695249d`)·10-17 09:00(quill, `e17aa4b`) 세 명이 다시 짧게 연쇄 실패하고 10-18부터 재정상화됐다.
- **`work/mechanic/2026-10-12.md:9`는 이 09-26·10-03 공백을 "로컬 기계가 꺼져 있던 구간으로 보여 별도 결함은 아니다"로 설명했다.** 커밋 작성자가 `github-actions[bot]`인 이상 이 설명은 틀렸다 — Actions가 로컬과 무관하게 자체적으로 실패한 것이다.

**위치**
- `git log --all --grep="근무 실패"` (전체 목록, 특히 2026-09-23~2026-10-05 구간)
- 커밋 `7c22aa0`(curator, 10-16 23:00) · `695249d`(scout, 10-17 07:00) · `e17aa4b`(quill, 10-17 09:00)
- `work/scout/2026-09-23.md` → `work/scout/2026-10-06.md` (중간 공백)
- 오진단: `work/mechanic/2026-10-12.md:9`

**고치는 법**
- 저장소에는 실패 원인(에러 메시지)이 안 남는다. GitHub Actions 탭에서 `curator.yml`/`scout.yml`/`quill.yml`/`mechanic.yml`의 09-23~10-05, 10-16~17 구간 실행 로그를 직접 열어 에러를 확인해야 한다 — 나는 WebFetch로 Actions 탭에 접근할 권한이 없어 여기까지만 확인했다.
- README "인증" 절이 이미 적어둔 대로 `CLAUDE_CODE_OAUTH_TOKEN`은 만료되면 `claude setup-token`으로 재발급해야 한다. 네 에이전트가 **같은 시기에 동시에** 실패하다가 **한꺼번에** 복구된 패턴은 토큰 만료/재발급 주기와 맞아떨어질 가능성이 가장 높다 — 토큰 만료 여부를 먼저 확인할 것.
- `.github/workflows/_agent.yml`의 실패 처리는 "상태 정리" 커밋만 남기고 실패 사유를 어디에도 기록하지 않는다. 최소한 실패 사유(exit code나 에러 메시지 앞부분)를 커밋 메시지나 이슈 댓글에 남기면, 다음엔 git log 고고학 없이 바로 원인을 알 수 있다.
